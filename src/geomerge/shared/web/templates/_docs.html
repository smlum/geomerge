What this is

A UI for a config-driven pipeline. Everything lives in plain files (YAML, CSV) that the UI reads and edits — the UI is a surface for reviewing those files, running the pipeline and checking what comes out.

Workflow

  1. Setup — target schema, matching rules for columns and classes.
  2. Collect — work through the provider checklist: find each dataset, complete its metadata, download the raw data.
  3. Prepare — map raw columns to the schema, run preprocessing, classify source values.
  4. Process — filter, add classified columns, calculate lengths, standardize geometry and formats, assign StatCan geographies, dedupe, merge.
  5. Validate — checks the data has to pass. (not built yet)
  6. Explore — maps and summaries of the results.
  7. Publish — the final release. (not built yet)

Notes and flags

  • Flag anything that needs doing; the note says what. Flags never change the pipeline — "excluded" does.
  • Review them on Home (Flagged view), or share FOLLOWUPS.md (geomerge tools followups).

Commands

  • geomerge serve — this UI.
  • geomerge pipeline run [--stage NAME] [--source ID] — run the pipeline.
